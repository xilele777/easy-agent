# 核心调用链：一轮请求如何完成

## 1. 从输入到 QueryEngine

入口先区分交互模式和 `-p/--print`。交互模式的 [`useAgentSession`](../../src/ui/hooks/useAgentSession.ts) 处理输入、会话保存和界面状态；Headless 的 [`runHeadless`](../../src/entrypoint/headless.ts) 合并管道输入与命令行 Prompt，再以同一个 [`QueryEngine.submitMessage`](../../src/core/queryEngine.ts) 提交。

`submitMessage` 先判断是否为内置斜杠命令、自定义命令或 Skill 调用。普通请求进入内部提交路径：可插入 Plan 附件、后台 Agent 通知、团队邮箱消息和图片块，然后把用户消息加入当前上下文。此处还有上下文预算与自动压缩相关逻辑；把“发给模型的消息”理解成由历史和这些附件共同组成更准确。

## 2. 从 QueryEngine 到 Agent 循环

`QueryEngine` 组装系统提示、当前模型、权限模式、工具上下文与取消信号，调用 [`agenticLoop.query`](../../src/core/agenticLoop.ts)。后者是异步生成器：一边执行，一边产出文本增量、工具状态、用量、错误和完成事件。交互界面与 Headless 消费同一事件流。

主循环可简化为：

```text
历史消息 + 系统提示 + 工具 Schema
  → 请求模型流
  → 收到 assistant 消息
  → 若无 tool_use，执行 Stop Hook 后结束
  → 若有 tool_use，执行工具并构造 tool_result
  → 将 tool_result 追加进历史，进入下一轮
```

真正的实现还有最大轮次、取消、Token 限额、响应截断恢复、上下文压缩和模型重试。学习时先找 [`query`](../../src/core/agenticLoop.ts) 的主 `while`、`streamMessage` 调用和 `stopReason` 分支，再看这些恢复路径。

## 3. 模型协议在哪里转换

[`resolveProfile`](../../src/services/api/providers/profile.ts) 决定当前模型协议。[`streamMessage`](../../src/services/api/streaming.ts) 把请求交给 Anthropic 路径或 [Provider 流适配](../../src/services/api/providers/providerStream.ts)。上层处理统一的流事件，无须在每个 UI 或工具模块里区分 GPT、Gemini、Anthropic。

调试模型兼容问题时，先定位是 Profile 解析、请求翻译、SSE 解析、结果归一化，还是 Agent 循环对结果的处理。相关离线特征测试在 [Provider 测试](../../src/scripts/test-providerstream-characterization.ts)。

## 4. 工具为什么不能直接执行

工具实现遵守 [`Tool` 接口](../../src/tools/Tool.ts)，由 [`tools/index.ts`](../../src/tools/index.ts) 注册。Agent 循环收到 `tool_use` 后，依次经过：

1. 按工具名查找当前可用实现。不存在则生成错误结果。
2. 执行 `PreToolUse` Hook，允许其阻止调用或改变权限行为。
3. 调用 [`checkPermission`](../../src/permissions/permissions.ts)，综合模式、规则、工具和输入判定 allow、ask、deny。
4. 对 ask 请求等待交互决定；Headless 没有交互界面时默认拒绝。
5. 执行工具本身。文件工具还有[工作区路径验证](../../src/tools/pathUtils.ts)；Shell 可选[宿主沙箱](../../src/sandbox/)。
6. 收集工具结果，必要时执行后置 Hook，生成与 `tool_use_id` 一一对应的 `tool_result`。

这里的边界非常重要：工具是否出现在模型 Schema、权限是否放行、宿主执行是否被隔离，是三个不同问题。Plan Mode 主要在执行时限制读写；并非简单地从模型可见工具列表里删除所有写工具。

## 5. 并发与顺序

[`runTools`](../../src/core/agenticLoop.ts) 根据 `isConcurrencySafe` 将连续安全调用组成批次，最多同时运行 10 个。同批异步完成顺序可以不同，但结果数组仍按模型发起的顺序构造，以满足工具调用和结果配对。文件写入、编辑和 Shell 等不安全批次串行执行。

若未来新增工具，必须审慎实现 `isConcurrencySafe`：只要两个调用可能共享文件、工作目录或外部状态，就不应宣称并发安全。

## 6. 结果如何落盘

`QueryEngine` 更新消息与累计 usage；[会话存储](../../src/session/storage.ts) 用 JSONL 记录消息、工具事件、用量、压缩和文件历史快照。`--resume` 从持久化数据恢复。文件回滚由 [`fileHistory.ts`](../../src/session/fileHistory.ts) 支撑。后台 Agent 输出与 Agent Teams 还各有自己的状态与文件布局，详见[团队状态文档](../../docs/agent-teams.md)。

## 建议自己做的三个追踪练习

- **只读问答**：从 `submitMessage` 追到 `streamMessage`，列出“无工具调用”的所有终止条件。
- **读文件**：从 `Read` 的注册追到权限、路径检查、结果写回；回答符号链接越界在哪里被阻止。
- **Headless JSON**：跟踪 `-p` 的输出对象，解释 `result`、`usage` 和退出码各从哪里来；当前 `total_cost_usd` 在 [`headless.ts`](../../src/entrypoint/headless.ts) 输出 `null` 表示暂无定价来源，不能当作零费用。
