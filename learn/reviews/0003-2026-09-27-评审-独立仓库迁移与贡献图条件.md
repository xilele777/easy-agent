# 独立仓库迁移与贡献图条件

## 当前状态

2026-09-27 核对 GitHub：`xilele777/easy-agent` 已属于用户本人，但它是 `ConardLi/easy-agent` 的公开 fork。默认分支是 `main`，当前工作分支 `codex/windows-next-stage-20260927` 比 `main` 多 16 个提交。最新提交在 GitHub API 中关联到 `xilele777`。

GitHub 个人贡献图通常要求提交位于独立仓库的默认分支（或 `gh-pages`），作者邮箱能关联账户。只把 fork 的远端 URL 换成另一个名称，或继续只在功能分支提交，都不足以满足这些条件。fork 上的提交通常要被上游合并后才计入个人提交贡献；迁到独立仓库后也应确认贡献图实际显示情况。

## 建议迁移路径

1. 在 `xilele777` 名下创建一个新的**非 fork** 公开仓库，名称与当前 fork 区分，保留现有 fork 作为来源记录。
2. 把当前 Git 历史推送到新仓库，并将现有 Windows 工作分支内容合入新仓库默认分支 `main`；先检查无密钥或本地配置被跟踪，再推送。
3. 将本地 `origin` 指向新仓库，并把旧 fork 保留为只读 `upstream-fork` 远端；更新 README 中仓库链接、徽章和发布配置中与旧地址相关的值。
4. 核对新仓库不是 fork、`main` 包含本次提交、提交作者被 GitHub 识别，再到个人贡献图确认结果。历史提交能否全部显示还受 GitHub 统计规则和刷新延迟影响。

这会创建公开仓库并改写本地发布目标，执行前需要确认新仓库名称及是否允许创建、推送。迁移后应保留 MIT License 和原作者署名，项目介绍明确基于上游二次开发。当前 CI 和文档规则调整可以先在现有仓库完成。
