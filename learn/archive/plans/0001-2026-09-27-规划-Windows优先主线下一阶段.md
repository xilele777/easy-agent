# Windows 优先主线下一阶段计划

> 制定日期：2026-09-27。依据[第一阶段进度核验](../../changes/0001-2026-09-27-改造-Windows可移植性第一阶段进度核验.md)和[原优化路线](../../plans/0000-2026-09-26-规划-优化与拓展路线.md)。代码基线为 `3abd6df`：Windows 本机默认离线门禁 57 通过、2 个 POSIX 用例跳过、0 失败。本计划是新阶段记录，原计划保留为历史基线。

## 目标与范围

下一步沿原路线的 **A：Windows 优先的 Coding Agent** 推进。先补齐第一阶段的跨平台证据，再交付可复现的 Windows 工作流：搜索代码 → 只读计划 → 经权限确认修改 → 查看 diff → 回滚。完成后应能指出哪些能力经过 Windows、Unix 和真实模型验证，哪些仍是限制。

本阶段聚焦 Windows 优先主线。Windows 宿主沙箱仍按[现有说明](../../../docs/sandbox-security.md)单独立项；Shell 可运行不代表已有沙箱隔离。

## 里程碑 1：补齐第一阶段验证

| 工作 | 执行方式 | 完成标准 |
| --- | --- | --- |
| 验证 Unix 可移植性 | 在 Linux 和 macOS 的同一代码基线上运行 `npm run verify:production`；记录系统、Node 版本、提交号及门禁汇总。重点核对 `Grep`、路径边界、Hooks 和 Bash 流式用例。现有 [CI](../../../.github/workflows/ci.yml) 在 Linux 跑完整门禁，在 macOS 只跑核心组，因此需补跑 macOS 完整门禁。 | 两个平台默认门禁均无失败，且 `hooks`、`bash-stream` 实际执行通过；失败时先留下可复现的缺陷记录再修复。 |
| 复核 Windows 偶发清理风险 | 针对曾出现 `EBUSY` 的 `agents`、`stage20`、`stage23` 用例重复运行，保留失败时的句柄/子进程线索；对照[测试说明](../../../docs/testing.md)确认临时用户目录隔离。 | 能说明清理问题是否仍可复现；若复现，修根因并通过对应回归，不以单纯增加重试次数作为完成依据。 |
| 固化跨平台门禁 | macOS 和 Windows 当前 CI 只运行核心组。待两平台完整默认门禁通过后，调整 [CI](../../../.github/workflows/ci.yml) 让后续提交持续运行完整离线门禁。 | Linux、macOS、Windows 的默认离线门禁在 CI 中都实际执行且通过；`platform` 和 `live` 仍按各自条件单独运行。 |

上述验证只补当前已知缺口。[`platform` 组](../../../docs/testing.md)涉及宿主沙箱，[`live` 组](../../../docs/testing.md)涉及真实服务，结果应另行记录，不混入默认离线门禁结论。

## 里程碑 2：补足 Windows 工作流的回归覆盖

先对照现有的[路径边界](../../../src/scripts/test-path-boundary.ts)、[受控子进程](../../../src/scripts/test-controlled-process.ts)和[Windows Shell](../../../src/scripts/test-windows-shell.ts)用例列出已覆盖行为，只对缺口补测试或修复。优先检查：项目内外符号链接、临时目录清理、PowerShell 命令取消后子进程是否退出，以及缺少解释器时的诊断。

完成标准：在隔离的临时工作区运行相关回归，工作区外文件保持不变；取消命令后无残留子进程；失败诊断能定位依赖或环境问题。每项实际代码改造完成时，按根目录规则新增 `learn/changes/` 记录。

## 里程碑 3：交付 Windows 端到端演示

1. 准备一个小型临时示例仓库和明确的目标修改，保存初始文件、预期结果与复现命令，不使用真实项目作为可写夹具。
2. 在 Windows 交互模式走通 `Grep` 搜索、只读 Plan Mode、权限确认后的文件修改、`/diff` 检查和 `/rewind` 回滚；验证计划阶段没有写入，回滚后文件与初始状态一致。
3. 以现有 CLI 本地模型夹具为起点，扩展出覆盖工具调用与结果回填的可重复离线回归；另用真实模型完成至少一次相同流程并记录脱敏输入输出、退出状态和失败点。没有凭证时先交付离线证据，将真实模型结果明确标为待验。
4. 将可复现操作步骤放在 `docs/`，同步检查 README 的 Windows 支持说明，并为这次改造新增 `learn/changes/` 记录。

完成标准：他人能按文档在 Windows 复现整个流程；权限提示、改动 diff、回滚结果均有证据；默认离线门禁仍通过。只有离线夹具通过时，称为“离线工作流已验证”，不宣布真实模型场景完成。

## 阶段收口

汇总 Windows、Linux、macOS 的门禁与端到端结果，区分“已实现”“本机已验证”“跨平台已验证”“真实模型已验证”。第一阶段只有在跨平台门禁与清理风险得到结论后才收口；Windows 优先主线只有在端到端流程和真实模型验证完成后才标记交付。随后再按[原路线](../../plans/0000-2026-09-26-规划-优化与拓展路线.md)选择基准任务，统计成功率、失败类型、耗时及 Token 用量，用新文档记录结果，不改写旧记录充当新进度。
